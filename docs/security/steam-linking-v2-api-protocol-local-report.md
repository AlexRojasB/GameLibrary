## Implementation

- `SteamSecureLinkController`: fixed POST `/steam/link/v2/requests`, `/review`,
  `/confirm`, `/cancel`; anonymous GET `/steam/link/v2/callback`. Creation returns
  the trusted Steam URL **in its private 201 body**, not Location or an API start
  URL. No initial API target contains a secret/transaction locator.
- `SteamLinkActivation`: default-off SecureLinkingEnabled plus **hard-false build
  readiness**, validated configuration and a narrow SQL schema-compatibility check.
  Default shipped DI never admits v2 in any environment, including Development/Test
  with all flags true. Explicit external integration-host DI may substitute readiness
  only in Development/Test; Production/Staging reject the substitution too. No public
  config flag enables it. Missing schema/DB affects linking only, without v1 fallback.
- `SteamLinkConfiguration`: pinned Steam authorization/verifier origin/path, exact
  server-owned return_to and realm, trusted explicit frontend/API bases. Ignores
  request Host/forwarded headers. Local HTTP exception is explicit, test-host-only,
  literal loopback and one host across ports; no arbitrary local provider override.
  Tests substitute the provider boundary in memory, never real Steam.
- `SteamLinkBrowserBinding`: independent proof generated by existing Core, canonical
  32-byte B only in `__Host-GameLibrary.SteamLink.v2`; Secure/HttpOnly/None/Path=/,
  no Domain, original DB deadline and conservatively rounded-down Max-Age. Local
  test-host HTTP uses its distinct Lax/non-Secure name. Raw cookie headers are checked
  before parser collapse; no decoding, duplicate acceptance or legacy-name fallback.
  Only known successful creation issues proof; callback/review/confirm/cancel/errors
  never set, clear or refresh the slot. No recovery of raw S/B from SQL.
- Strict manual JSON envelope: 4 KiB including unknown-length streams, exact fields,
  duplicate decoded-property/type/UUID checks, JSON content type, validated signed
  JWT sub/exp, exact Origin and no query fallback. No client owner/provider/destination.
  Exact-origin credentialed POST CORS is limited to these four JSON operations;
  anonymous empty OPTIONS validates method/headers/Origin separately and performs no
  transaction/provider work. Untrusted preflight receives no allow-origin grant.
- `SteamOpenIdProtocol`: 16 KiB request-target cap, <=32 parameters, <=128-byte keys,
  <=8 KiB values, strict UTF-8/percent decoding and duplicate decoded-key rejection.
  Exact ns/mode/provider/return_to/identity/optional realm; canonical UInt64 identity;
  required sig/assoc_handle/nonce/signed coverage; no extensions or mixed negative
  fields. Nonce freshness uses locked PostgreSQL creation/current time before I/O,
  and Core repeats it after provider/lock/write waits. No local signature/association
  mode or nonce table; stateless OP one-use nonce behavior remains an explicit trust.
- Callback proves B/live phase before verification, holds **no SQL lock during I/O**,
  then reuses Core staging. A changed expected-URL configuration fails closed. A
  pause stops newly admitted work, not earlier admitted work: a tested flag flip does
  not pretend to revoke a callback already in verification. Callback never links,
  echoes errors/assertions or changes cookies, and uses fixed frontend review/failure
  303 destinations. Cancel/setup_needed/error/malformed provider returns never mutate.
- `SteamClient`: pinned check_authentication POST, no application cookies/JWT/state/
  owner/T forwarding (return_to necessarily contains S), no redirects, no CookieContainer,
  no retry, no HTTP logger or Activity-header propagation. Strict 200/direct key-value
  namespace/one is_valid:true parsing, no duplicate/contradictory fields, strict UTF-8,
  8 KiB **decoded stream** cap and one configured 1–30s deadline covering headers/body.
  Provider Set-Cookie is ignored by the configured cookie-disabled handler. Existing
  owned-games/import logic is otherwise unchanged.
- Core remains internal (friend access for Api, not new public unchecked linking
  methods). Existing proofs, locks, DB time/JWT eligibility, immutable staged identity,
  expected-ID compare, atomic consumption/account/receipt and conservative COMMIT
  reconciliation remain authoritative. Review uses fresh-primary reconciliation;
  no prior review call/token is required. Sensitive result contracts redact ToString.
- Unlink now uses a clean context and Library→v2-row locks, cancels live v2 rows and
  deletes only the current account atomically. Consumed receipts/catalog/imports
  remain. It works while linking is disabled and with the previous schema; a narrow
  cancellation projection also works if full v2 schema compatibility fails. Signed
  JWT expiry is rechecked for HTTP unlink. Unknown COMMIT remains unknown, not rollback.
- Five/minute creation and separate 30/minute owner-operation windows per validated
  sub; four in-flight callbacks per instance, no queues. Retry-After is retained for
  windows and explicitly 1s for callback concurrency. Existing cover/import policies
  and limits are unchanged.
- Early privacy covers successes, challenges, errors, redirects, OPTIONS and unknown
  Steam paths: private,no-store / no-referrer / nosniff and Origin/Authorization Vary.
  Safe allowlisted ProblemDetails never echoes input/SQL/provider/exception values.
  Existing payload-free diagnostics and suppression of sensitive handled-exception
  emissions remain, with ordinary useful warnings intact. No request/response body
  or header capture middleware was introduced. Incoming parser/ingress diagnostics
  before the application remain outside this guarantee. Kestrel's request-line limit
  permits the specified 16 KiB target plus method/version framing; protocol enforces
  the exact target bound independently, not by truncating it.
